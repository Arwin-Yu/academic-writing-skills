# write-review

围绕段落要建立的研究判断组织文献，写清已有研究共同说明了什么、依据是什么，以及结论适用于哪些条件。标题、大纲和草稿用于理解写作意图；正文从经证据支持的论点展开，不逐条扩写大纲或逐篇串讲论文。修改技能本身不启动论文写作。

## 1. 提炼核心论点

读取目标标题、大纲或草稿及必要上下文；来自 deepresearch 时，承接已有研究问题、阶段性结论和证据映射。先用一句话明确本段要建立的判断及其在整节中的作用，不用主题名称、论文名单或工作指令代替论点。定义、背景和承接段说明要建立的认识即可，不强求新贡献。

沿用已确认的范围与章节分工。区分材料支持的判断、本文解释和待证主张；仅有标题或意图时先形成暂定论点，不补造结论。不同理解会实质改变论证时再询问。

## 2. 确认论据

按论点选择文献，复用版本明确、位置可定位的原文和已核实记录。机制查方法，效果与局限查相应实验或讨论；新增细节定向补读，不重做整轮调研。摘要、旧稿和模型记忆不能代替未核实的细节。

分清原作者报告、实验观察和本文综合解释，主张范围与证据覆盖相称，不规定引用数量。证据不足或冲突时调整论点、收窄表述或标明缺口，不筛去相反结果维持叙述；尚未找到证据不等于相关研究不存在。

## 3. 围绕论点组织正文

先安排判断之间的关系，再决定论文、机制与结果的出现顺序。大纲节点与自然段不必一一对应，按论证需要合并或拆分，保留整节的问题与推进关系。材料承担提出判断、解释、举证、比较或限定等作用；删除与论点无关的旁支，避免重复相邻段落。段落可以按任务采用不同结构，不机械套用“问题—方法—结果—局限”，也不把整节的全部要求压入每段。

解释设计时，说明针对什么困难、改变了什么、这种改变如何可能起作用，以及有哪些验证和限制。模块名称、术语与操作步骤不能代替作用解释。按目标读者和已有上下文补充必要定义；只有影响当前论证时，才展开输入输出、训练与使用的区别或实现细节。

论述转向新的对象、属性、过程或分析层次时，补清它与当前判断的联系。结论依赖的中间前提应能从正文及必要上下文中找到；不能仅用连接词跨过推理缺口，也不为补齐因果链而添加未经证实的机制。理论内容交代假设与推导范围，实证内容区分观察、解释和因果主张。

比较围绕共同问题展开，依据结果、能力、条件与代价说明差异，不只列模块。任务、数据、评价指标或运行条件不一致时保留差异，不直接排名。区分并行、互补、继承和针对性改进；年份先后不能证明发展关系。

明确句子的主语、动作与对象，直接陈述具体机制、发现或局限。删去空泛开场、重复总结和未增加信息的“作者进行了讨论”等转述，保留必要的证据归属。组织、选材和核查指令留在底稿；有实际信息的分类依据、范围说明和章节导航可以进入正文。

收束时回答本段建立了什么认识及其边界；小节总结综合原问题的解决程度与剩余困难，不逐篇压缩复述，不凭空添加未来方向。缩短时优先删重复和旁支，保留核心判断、必要前提与证据条件。

## 4. 验证、修复与交付

先不看提纲，只读成稿和必要上下文，复述本段的核心认识、支持它的理由及其与相邻段落的联系。复述须能对应正文中的具体陈述，不能借底稿补出未写明的前提。再对照原文和记录，核查主张的证据、归属、版本、条件与表述强度。

按实际问题修复，不以自评“通过”代替验证：

| 不符合标准的表现 | 处理方式 |
| --- | --- |
| 只能复述主题或论文名单，说不清本段建立了什么判断 | 回到第1节明确论点，再按第3节重组；材料不足以支持论点时转第2节，不凭空拔高结论。 |
| 技术介绍流水账：以罗列论文、模块或步骤代替论证，只交代“做了什么”，没有解释这些材料如何支持本段判断；首尾附有论点也不算通过 | 回到第3节，按核心判断、共同问题及证据关系重新选材和组织，解释关键设计的作用、差异及其意义，保留必要的机制说明。缺论点回第1节，缺支撑回第2节；不能只加过渡词或泛泛总结。 |
| 只能列出模块或步骤，必要性、作用或中间关系仍依赖读者猜测 | 回到第3节补清必要前提、对象与作用，或调整叙述顺序；缺少事实依据时转第2节，不只补连接词。 |
| 相邻内容只有主题相关，重复展开，或总结不能从前文推出 | 回到第3节合并、重排或删除旁支；并列内容说明共同目标，收束限定在前文已有依据的认识内。 |
| 具体主张缺证据、比较条件不一致、概括过宽，或把解释写成已证实结论 | 回到第2节定向核查，再补足条件、降低表述强度、改作有依据的定性比较，或撤去不成立的推论并修正正文。不能靠润色保留不成立的判断。 |

修改后重读受影响的段落、相邻承接和相关结论，并复查受影响的证据。只要同一断点仍在，就继续修复；仅换措辞、删连接词或缩短句子不算解决。引用存在或脚本通过也不能证明内容成立。

无法在现有材料与授权范围内修复时，停止扩写依赖该缺口的内容，交付可成立的部分，明确未解决的主张或推理断点、缺少的材料或未解决原因，以及受影响范围。核心论点仍不成立时标为待补草稿，不作为完成稿交付；不通过删除用户已确认的研究问题来规避缺口。

默认交付一句核心论点、正文及必要的未解决问题；用户只要正文时，过程检查留在工作记录中，但影响正文成立的缺口仍须简要说明。通过上述内容检查后再处理翻译和排版，不用格式完成代替内容完成。

沿用用户指定的语言、篇幅、格式及项目已有约定，不强制创建配置或审查文件。文件任务保留修改前版本，只改授权范围，沿用已有文献标识与引用方式；按项目需要检查编译及修改页，如实说明实际完成的检查与剩余缺口。
