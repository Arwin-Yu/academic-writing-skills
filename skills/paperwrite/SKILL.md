# paperwrite

把研究材料写成有依据、可理解的科研论述。组织约定约束写作操作，留在底稿，不直接转写为正文。修改技能本身不启动写作；用户另有正文修改要求时按其范围执行。

## 1. 确定本节贡献

读取实际目录、相邻正文和本章文献包。底稿分开记录组织、选材安排与文献支持的研究论点；正文从研究论点起草，不沿组织安排逐句扩写。用户要求怎样组织章节，不自动构成领域事实。
介绍具体工作前，按[原文核验与记录](../deepresearch/references/chapter-records.md)查阅与拟写主张对应的原文，确认作者、题名、版本及实际阅读范围。可复用可定位的原文缓存和已核实片段；文献包概述、大纲、旧稿及模型记忆不能代替原文。核验依据留在现有底稿，不另建重复文献库。
先确定本节新增的判断，再整理最小比较底稿：共同问题、比较维度、各方法的依据与结果。只有背景常识或重复前节，不足以扩成一节；在授权范围内重新组织。
按论点选择论文及顺序，不照抄前节的论文名单和介绍次序。复用论文须回答新问题，已讲过的机制简引前文。

## 2. 解释关键设计

从具体任务和原有困难出发，解释方法改了哪个对象、怎样改变、为什么能缓解困难，再给对应结果及条件。先让读者理解一个关键操作，再比较其他方法；不要连续切换模型和模块。
首次使用特征、编码、解码器等对象时，说明它实际存储或处理什么。交代训练时学什么、使用时计算或优化什么。“采用网络”“加入约束”和执行步骤本身不能代替有效原因。
对象发生变化时补足前提。例如，讨论改色突然转向几何损伤，必须说明该步骤也改写了哪些几何属性；说明动画中的纹理对应，必须说清运动后哪个部位仍读取哪处颜色。
先从摘要、引言或结论确定与本节有关的关键贡献；机制描述核对方法及图式，效果与局限核对实验或讨论。模型经验只作理解和检索线索，不能补出原文未核实的模块、参数或结果。
只展开支撑本节论点的机制，缩短时减少旁支，保留关键设计及因果。缺少相应原文就定向补读；仍无法核实时收窄表述或列明缺口，不凭摘要推测细节，不重做整轮调研。综述推理与作者报告分清，不把合理解释写成实验结论。

## 3. 比较与收束

用同一问题比较方法的结果、适用条件与代价，分清替代方案、互补方案和有证据的后续改进。补充会改变路线判断的相关工作，不用单篇代表全领域，也不凑引用数。
涉及效率，报告原文时间、计时步骤、输入、硬件及质量条件；条件不同可并列注明，不能直接排名。其他比较同样需要能力或结果依据，不能只列模块差别。
总结围绕研究问题综合“已做到什么程度 → 具体困难及其原因”。句间有因果、条件或推导，不逐篇复述技术，不用抽象否定句或给作者、设计者的任务清单代替结论。引用紧邻实际主张，保留版本与证据边界。

## 4. 检查实际正文

先不看底稿逐段读成稿：句子是在说明研究对象，还是安排作者怎样分类、选材、比较和核对？写作操作移回底稿；必要的分类依据、章节导航、技术前提和证据范围保留，并说明具体对象。例如，“同一工作可在不同小节支持比较”属于底稿，正文应说明方法中哪些机制可以配合及其作用。不能仅凭“需要”“比较”等词判错，也不能只换主语或改成陈述句。
逐篇对照成稿和原文，核查每项具体主张的证据位置、阅读范围及表述强度，并反查与本节有关的关键设计是否遗漏。没有对应原文不能标记已核实；引用存在或脚本通过不能代替这项检查。
保留初稿和比较底稿，再按 [rewrite 执行检查](../rewrite/references/execution-checks.md) 检查实际文字。在现有审查记录中保留处理过的原句与理由，以及应保留的技术前提、分类定义或范围说明；没有问题的短稿如实记录。读过规则、声称通过、句子变短，都不算完成。缺少内容返回写作，不能用润色掩盖证据或论点缺失。
只在内容与可读性核查后处理双语、引用和排版。交付说明实际完成的检查和剩余问题，作者是否认可另行记录。

执行前定位项目已有的写作约定、决策记录、文献库和语言流程；如有 `writing-contract.md`、`review-state.json`、`decisions.md` 或 `BILINGUAL_WORKFLOW.md`，读取与本轮相关的内容。用户最新明确指令优先。未配置这些文件时，使用当前对话和项目实际文件，不强制创建配置文件，也不虚构既有决定。文件任务备份旧稿，内容核查后按项目配置编译并查看修改页；对话测试按用户指定范围执行。保留其他章节、标签和共享文献库。
