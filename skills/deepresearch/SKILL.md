# deepresearch

围绕本章研究问题，讲清为什么需要解决、技术怎样起作用、已经解决到哪里、剩余困难是什么，以及后续工作怎样回应。
先确认目录，再用达标文献形成有实质结论的章节大纲；在 `temp/` 保存文献摘要和论点依据，供后续写作与 `cite` 使用。修改本技能时不启动调研。

执行前定位项目已有的写作约定、决策记录、文献库和语言流程；如有 `writing-contract.md`、`review-state.json`、`decisions.md` 或 `BILINGUAL_WORKFLOW.md`，读取与本轮相关的内容。用户最新明确指令优先。未配置这些文件时，使用当前对话和项目实际文件，不强制创建配置文件，也不虚构既有决定。

## 1. 关键词与范围确认

- 用户须提供至少一个研究关键词。没有则先询问；本轮已提供则直接使用。
- 针对每个关键词给出三个具体的研究范围选项，每项用一句话说明研究什么，并标出推荐项。
  例如“3DGS 头部”可细分为建模表示、动画驱动、对话交互；选项应随关键词变化。
- 用户可以单选、多选或补充方向。等用户确认后再检索；已有明确确认的选择不重复询问。
- 根据当前对话和项目主稿的现有结构定位目标章节；无法判断归属时才询问。未限制年份则检索所有年份，同时检查近期进展。

## 2. 章节结构设计与确认

- 先读前面章节的目录和内容职责，说明本章需要承接什么、补充什么，避免重复。
- 按需要回答的问题重新设计目录，子章节不超过 5 个。旧目录只用于检查遗漏，不默认沿用；不能用方法名称或处理步骤代替研究问题。
- 在对话中给出候选目录、每节的具体问题及其重要性、排列理由和与前章的边界，明确征求用户同意。
- 用户确认前，只检查已有本地材料，不开展新文献检索、正文起草或 TeX 修改。
  用户确认后再进入第 3 步；本轮已明确确认的目录不重复询问。

## 3. 搜索与筛选

用 **Google Scholar（谷歌学术）** 检索。查询包括关键词及英文同义词、
“关键词 + 任务/机制”、"关键词 + survey"，再追踪代表论文的参考文献和 Scholar 的 “Cited by”。
分别查看相关结果和近期结果；记录查询、日期、实际查看范围及候选论文。

Scholar 不可用时，改用 **Semantic Scholar 或 OpenAlex**，结合 **DBLP** 和官方论文集核对身份，
并记录替代来源。所有外部检索都不可用时，只整理已有材料并标记“外部检索未完成”。

先定位项目已配置的文献库和原文缓存，复用已有的可核验证据，围绕尚未回答的问题补查，不为凑文献数量扩大检索。
独立查询尽量批量进行；同一入口明确被拒绝访问后，本轮改用其他来源，除非访问条件改变，不反复尝试。

论文须与本章相关，且**至少满足以下一项**，才可作为本章参考：

| 条件 | 核验方法 |
|---|---|
| 发表于 CVPR、ICCV、ECCV、AAAI、ICLR、NeurIPS、ACL、EMNLP | 查官方主会论文集；workshop 和 Findings 不按主会条件通过，但仍可检查另两项 |
| 所在期刊的 Journal Impact Factor（JIF）**大于 10** | 以检索时最新发布的 JCR 年度为准；查 Clarivate JCR 或明确标注该年度的期刊官网 |
| 该论文被引用次数**大于 5000** | 默认查 Scholar；不可用时用 Semantic Scholar 或 OpenAlex，记录计数来源与日期 |

只需核实一项通过，不必查完三项。JIF 恰为 10、引用恰为 5000 均不通过对应条件。
不能用 CiteScore 代替 JIF，不能用作者总引用或相加多个数据库计数代替单篇引用数。
三项均不满足则排除；没有一项已核实通过、但仍有条件无法核实时，标为待核验，暂不参考。
不适用的条件按不满足处理；最新年度 JIF 查不到时，该条件记为待核验，不拿旧值替代。
已有库内论文同样执行此规则；不修改原库的纳入决定。预印本须核对已录用版本或另两项条件。
达标仅表示可继续阅读，最终还须检查论文是否支持本章具体论点。

## 4. 阅读并记录文献

围绕大纲中拟写的判断定向阅读原文。按 [原文核验与文献记录](references/chapter-records.md) 确认作者、题名及实际阅读版本；贡献概述查摘要、引言或结论，机制查方法及图式，效果和局限查对应实验或讨论，理论结论核对假设与推导范围。只读摘要不补写未核实的细节，模型记忆和经验不能作为论文事实的依据。

复用版本明确、位置可定位的原文缓存及已核实片段，阅读时持续记录，不等结束后凭记忆补写。每篇保留书目信息、准入依据、摘要概述和实际阅读范围；摘要概述与基于正文的分析分开，未取得的信息留缺并说明原因。

以“拟写判断—原文依据”为主要记录单位，在现有文献包中关联大纲节点、文献 ID 和证据 ID，不只保存论文摘要或名单。每项拟采用的主张须能查到：

| 记录内容 | 要求 |
| --- | --- |
| 拟写判断与用途 | 写出具体陈述及所服务的段落问题，说明证据支持、反驳或限定判断的哪一部分。 |
| 原文依据与位置 | 简短转述实际支持内容，记录原文链接或本地文件、版本及可定位的章节、页码、图表或公式；不能只记“有提升”或“支持该观点”。 |
| 依据性质 | 区分原作者主张、实验观察、理论推导与本文解释。解释设计时记录关键改变及作用依据，不用模块名或步骤代替原因；不把动机当作验证。 |
| 适用条件与边界 | 保留影响判断的任务、数据、指标、运行条件或理论假设；注明局限是原文报告还是本文分析，不将未报告写成不能实现。 |
| 核验状态与缺口 | 按实际阅读标为 `verified` 或 `needs_check`，写明尚缺什么、哪些陈述暂不能采用。核验仅表示原文支持对应陈述，不表示独立复现。 |

只记录支撑当前论点所需的内容，不要求每篇论文套用同一解释链。单篇工作的问题、设计和结果存入已有 `problem_analysis` 与 `evidence`；跨论文比较及综合判断放在大纲论证记录中，关联各项证据，说明由哪些已核实事实推出什么认识，保留分歧与条件差异。单条证据已核验，不代表跨论文概括或因果推论已经成立。

写入文献包前，检查后续 write-review 能否据记录定位原文、复述支持内容、区分原文结论与本文解释，并判断主张的适用范围。主张缺依据就定向补读；证据不足或相互冲突时收窄、修正判断或明确留缺，不筛去相反结果，也不凭经验补全。原文版本或拟写主张变化时复核受影响的映射，不要求全文重读或重做整轮检索。沿用现有 `references.md`、`references.json` 和记录格式，不另建重复文献库。

## 5. 按问题形成解释和结论

先确定整节要回答的一个总问题和最后应得出的结论，再组织段落。内部记录每段“承接前文什么 → 推进什么判断 → 留下什么供后文回答”；不能只列几个都与主题相关的问题。
以下六项用于判断整节是否充分，不要求每条都包含六项，也不固定段数或标题。每条承担整节论证中的一步，不必各自另起一个独立问题：

1. **问题是什么：** 谁在什么任务或条件下遇到什么困难，不能只列技术名词。
2. **为什么重要：** 不解决会影响什么能力、使用成本或结果；需要时用简短例子说明，不把设想用途写成已验证应用。
3. **技术怎样解决：** 解释关键设计为什么能缓解上述困难，将相关方法放在共同问题下比较。
4. **解决到什么程度：** 给出已验证的能力或改进及其数据、任务、硬件等适用条件；有可比数值才作定量比较，没有时给出有依据的定性边界。
5. **还缺什么：** 说明具体失败条件、局限来自哪里，以及它对原问题有什么影响，不能只写“仍有挑战”。
6. **后续怎样回应：** 指出后续工作针对哪项不足改变了什么、取得什么证据、还剩什么；没有核实到则明确写本次未找到，不编造发展链。

大纲条目应写出上述问题的实际答案和阶段性结论，不得用“比较 A/B”“考察效率”“核对局限”等工作指令代替调研结果。
开头先说明任务、使用目标和不解决的具体后果，再引出技术困难；不能用“必须”“重要”或抽象判断代替动机。
例子、方法和结果围绕总问题推进。先安排观点之间的依赖，再选择支持观点的论文；同一判断下比较相关设计，不按论文逐个另起话题。首次出现术语时，先说明它处理什么、做什么，再给名称。
并列分支须有共同目标和比较依据；分支结束要回到总问题，不硬造因果或发展顺序。新对象仅用于说明已有解释的适用边界时简短处理；无助于结论的旁支删去，不能靠过渡词或重复“仍有问题”连接独立段落。
论文用于支撑解释，不能按年份逐篇串讲。并行路线分别展开；只有明确依据才能写为继承、针对性改进或取代关系。
按主张选择引用：单篇结果只能支撑该案例；概括共同困难或比较路线时，须有相应范围的互补证据。不规定每段引用数量，也不把单篇局限写成领域共识。
比较须保留任务、数据和运行条件的差异；区分原文结果、本次分析和未来设想。找不到证据不等于该方向不存在。

## 6. 写入 TeX 与 temp

先按第 7 步检查实际大纲的解释和证据，修好后再同步写入和排版，无需增加用户确认环节。
**按第 2 步经用户确认的目录，将调研大纲写入项目实际使用的 TeX 主稿和目标章节**。先从项目入口、编译配置及已有文件识别主稿，不要求用户重复指定可以判断的文件。只更新本轮约定的语言；项目要求双语时再同步两语。用户指定仅在对话中测试时按其要求执行。
使用对应标题和条目显示待审大纲，每节写出第 5 步的实质结论及与相邻节的联系。双语项目保持结构、论点和证据边界一致。
已有正文保留，只更新已有大纲或追加待审大纲；不在本流程扩写正文，不另建 `outline.md`。
如项目使用 `SYNC-ID`，保留已有标记；为大纲节点设置稳定标签，双语项目使用对应标签；文献、证据与节点的关系存入参考文献包。

在当前稿件目录新建或复用 `temp/<chapter-id>/`，保存：

- `references.md`：简短调研结论，以及带摘要、本章用途和证据位置的章节参考文献；另列未选用、待核验和排除记录。
- `references.json`：同一组文献、大纲映射、筛选依据、检索记录和检查结果，供后续 `cite` 读取。

复用原库 ID；库外论文使用章节临时 ID。不自动修改共享 BibTeX 或正式文献库，不自动清理 `temp`。
优先使用现有工具和直接编辑，文献包两种格式取自同一组记录，避免为单次大纲另建大套生成、验证和预览脚本。
内容稳定后按项目配置编译本轮修改的语言并检查目标页；仅有错误或影响阅读的问题才继续修复，不为独立预览反复调整分页、导出截图。
仅在对话中测试时，直接展示问题、结论和参考文献；不写文件、不编译，文件类检查记为不适用。

## 7. 检查、补救与交付

| 检查什么 | 不通过时怎么办 |
|---|---|
| 本章目录已经用户确认，子章节不超过 5 个，与前章分工清楚 | 回到第 2 步调整并征求同意，不能直接改稿 |
| 整节回答第 5 步六项问题；各段对总问题作出具体推进，隐去论文名仍能说清设计改变及作用 | 仅列术语、结论或“比较/考察”指令即不通过；缺解释回第 5 步，缺依据回第 3、4 步，不把六项压进每条 |
| 不看段落计划，只读实际大纲，能复述总问题、每段推进及最终结论；段落相邻的理由具体成立 | 声称递进的段落调换后仍不影响论证，或只能说各段主题相关时，先合并、重排或删减；真正并列的部分明确共同目标，不强求先后，也不靠补过渡句判为通过 |
| 相邻句能回答“前句留下什么问题、后句为何回答它”；换对象时说明与本节目标的关系 | 只能说两句主题相关，或靠“因此”连接却无中间理由，即不通过；补足原因或调整顺序，删掉无关旁支 |
| 发展关系有依据；每项局限与后续回应对应，未找到回应或证据的地方已明确说明 | 查明后续工作实际解决的对象；无法证实时改为并行比较或明确缺口，不能用年份补成因果链 |
| 每篇推荐文献相关、达标；拟写主张有对应原文，阅读深度匹配，且未遗漏与本节有关的关键设计 | 定向补读相应章节；纠正、收窄或删除未核实表述，补回被泛化概括掩盖的关键设计；不能删掉已确认的研究问题来判定通过 |
| 已参考文献没有漏记，摘要、版本和证据位置准确 | 补齐记录，纠正误述，再核对相关节点 |
| 节点与文献映射正确，JSON 可解析；要求双语时两语结构和意思一致 | 对照实际条目修正映射；双语任务再检查翻译和同步，单语任务记同步不适用 |
| 本轮修改的 TeX 能按项目配置编译，大纲在 PDF 中完整可见 | 使用项目已有编译器配置；查看 PDF，修复本轮引入的错误、缺字或内容截断 |

先检查整节推进，再检查段内解释、证据，最后检查双语和编译；记录实际文字中的承接与断点，不能用计划表、引用数量、字段齐全或脚本通过代替内容检查。
用户因解释质量要求改技能时，先用已授权的一个问题小节验证修订，不自动扩写整章或改其他章节；不能以已改规则宣称可读性获认可。
修正后只复查受影响部分。围绕明确缺口尝试新的有效查询或来源；同一缺口已无新的可行路径时停止重复检索，不为形式完整持续扩展任务。
核心问题仍缺证据时，在大纲中按输出语言标明“证据不足”或“Insufficient evidence”；其他问题记录实际原因。
任一必需检查未通过或未执行，保留已完成部分，整体状态记为 `needs_work`。
工具缺失、来源无法访问或既有编译错误也要如实记录，不能写成已检查通过，不自行放宽筛选条件。
全部检查通过才记为 `complete`；这只表示调研交付完整，不代表用户已认可大纲。
交付本轮实际修改的 TeX 和文献包链接（对话测试除外），分别报告内容、证据、双语与技术检查，以及未完成项和下一步。
按实际记录简述检索阅读、综合组织、编译整理的耗时；无法精确拆分时说明估计范围，不编造逐项计时。
`cite` 使用记录时仍须对照实际写出的论点复核。
