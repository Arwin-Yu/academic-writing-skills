# deepresearch

围绕本章研究问题，讲清为什么需要解决、技术怎样起作用、已经解决到哪里、剩余困难是什么，以及后续工作怎样回应。
先确认目录，再用达标文献形成有实质结论的章节大纲；在 `temp/` 保存逐篇研究记录和论点依据，供后续写作与 `cite` 使用。修改本技能时不启动调研。


## 1. 关键词与范围确认

- 用户须提供研究至少一个研究关键词。没有则先询问；本轮已提供则直接使用。
- 针对每个关键词给出三个具体的研究范围选项，每项用一句话说明研究什么，并标出推荐项。
  例如“3DGS 头部”可细分为建模表示、动画驱动、对话交互；选项应随关键词变化。
- 用户可以单选、多选或补充方向。等用户确认后再检索；已有明确确认的选择不重复询问。
- 根据当前对话和项目主稿的现有结构定位目标章节；无法判断归属时才询问。未限制年份则检索所有年份，同时检查近期进展。

## 2. 章节结构设计与确认

- 先读前面章节的目录和内容职责，说明本章需要承接什么、补充什么，避免重复。
- 按需要回答的问题重新设计目录，子章节不超过 5 个。旧目录只用于检查遗漏，不默认沿用；不能用方法名称或处理步骤代替研究问题。
- 在对话中给出候选目录、每节的具体问题及其重要性、排列理由和与前章的边界，明确征求用户同意。
- 用户确认前，只检查已有本地材料，不开展新文献检索、正文起草或 TeX 修改。
  用户确认后再进入第 3 步；本轮已明确确认的目录不重复询问。

## 3. 搜索与筛选

用 **Google Scholar（谷歌学术）** 检索。查询包括关键词及英文同义词、
“关键词 + 任务/机制”、"关键词 + survey"，再追踪代表论文的参考文献和 Scholar 的 “Cited by”。
分别查看相关结果和近期结果；记录查询、日期、实际查看范围及候选论文。

Scholar 不可用时，改用 **Semantic Scholar 或 OpenAlex**，结合 **DBLP** 和官方论文集核对身份，
并记录替代来源。所有外部检索都不可用时，只整理已有材料并标记“外部检索未完成”。

先定位项目已配置的文献库和原文缓存，复用已有的可核验证据，围绕尚未回答的问题补查，不为凑文献数量扩大检索。
独立查询尽量批量进行；同一入口明确被拒绝访问后，本轮改用其他来源，除非访问条件改变，不反复尝试。

论文须与本章相关，且**至少满足以下一项**，才可作为本章参考：

| 条件 | 核验方法 |
|---|---|
| 发表于 CVPR、ICCV、ECCV、AAAI、ICLR、NeurIPS、ACL、EMNLP | 查官方主会论文集；workshop 和 Findings 不按主会条件通过，但仍可检查另两项 |
| 所在期刊的 Journal Impact Factor（JIF）**大于 10** | 以检索时最新发布的 JCR 年度为准；查 Clarivate JCR 或明确标注该年度的期刊官网 |
| 该论文被引用次数**大于 5000** | 默认查 Scholar；不可用时用 Semantic Scholar 或 OpenAlex，记录计数来源与日期 |

只需核实一项通过，不必查完三项。JIF 恰为 10、引用恰为 5000 均不通过对应条件。
不能用 CiteScore 代替 JIF，不能用作者总引用或相加多个数据库计数代替单篇引用数。
三项均不满足则排除；没有一项已核实通过、但仍有条件无法核实时，标为待核验，暂不参考。
不适用的条件按不满足处理；最新年度 JIF 查不到时，该条件记为待核验，不拿旧值替代。
已有库内论文同样执行此规则；不修改原库的纳入决定。预印本须核对已录用版本或另两项条件。
达标仅表示可继续阅读，最终还须检查论文是否支持本章具体论点。

## 4. 阅读并记录文献

先理解每篇拟采用文献的研究，再选择它对综述论点的用途。按 [原文核验与文献记录](references/chapter-records.md) 确认作者、题名及实际阅读版本，为每篇分别记录以下五项：

| 记录项 | 需要说明的内容 | 主要阅读位置 |
| --- | --- | --- |
| 研究问题 | 具体研究什么任务或困难，问题在什么条件下成立 | 优先摘要；不足时补读引言 |
| 动机 | 现有研究哪里不足，为什么需要解决，不解决会影响什么 | 优先摘要；不足时补读引言，与研究问题分开记录 |
| 方法 | 核心思路、关键设计及作用依据，怎样回应上述问题；不能只列模块或步骤 | 以方法及相关图、公式为主，讨论和结论补充解释 |
| 局限性 | 依赖的假设、适用条件、失败情形及尚未解决的问题 | 方法、讨论和结论；涉及实际失败或性能边界时核对实验 |
| 贡献 | 作者声称新增的方法、理论、数据或发现，以及相对已有研究的改变 | 优先引言末尾的贡献陈述；涉及效果时另核对实验，理论结论核对推导 |

五项分别概述，不用整段摘要或“本章用途”代替。每项关联具体证据 ID，保留原文内容的简短转述、可定位的章节/页码/图表公式、版本和实际阅读范围；同一证据可复用，不必重复抄录。未读到所需章节与已读范围内未找到相关陈述须分清，缺项写明原因，不凭经验填齐。尚未采用的候选论文按实际阅读记录，不强行补成完整分析。

贡献陈述属于作者主张，不能自动视为已验证效果；区分原文报告、实验观察、理论推导和本文解释。局限也要区分作者说明与本次分析，不能把未报告写成不能实现。只读摘要不补写未核实的机制、数字或比较，模型记忆不能作为论文事实的依据。

在逐篇五项记录基础上，再于本章用途和大纲映射中说明哪些证据支持、反驳或限定当前综述判断。跨论文概括须交代共同问题、条件差异及推理依据，不将单篇结论推广到全领域，也不筛去相反结果维持预设观点。

复用版本明确、位置可定位的原文缓存及已核实记录，阅读时持续补记。主张缺依据就定向补读；证据不足或冲突时修正判断或明确留缺。版本或拟写主张变化时复核受影响内容，不要求全文重读或重做整轮调研。

## 5. 按问题形成解释和结论

先确定整节要回答的一个总问题和最后应得出的结论，再组织段落。内部记录每段“承接前文什么 → 推进什么判断 → 留下什么供后文回答”；不能只列几个都与主题相关的问题。
以下六项用于判断整节是否充分，不要求每条都包含六项，也不固定段数或标题。每条承担整节论证中的一步，不必各自另起一个独立问题：

1. **问题是什么：** 谁在什么任务或条件下遇到什么困难，不能只列技术名词。
2. **为什么重要：** 不解决会影响什么能力、使用成本或结果；需要时用简短例子说明，不把设想用途写成已验证应用。
3. **技术怎样解决：** 解释关键设计为什么能缓解上述困难，将相关方法放在共同问题下比较。
4. **解决到什么程度：** 给出已验证的能力或改进及其数据、任务、硬件等适用条件；有可比数值才作定量比较，没有时给出有依据的定性边界。
5. **还缺什么：** 说明具体失败条件、局限来自哪里，以及它对原问题有什么影响，不能只写“仍有挑战”。
6. **后续怎样回应：** 指出后续工作针对哪项不足改变了什么、取得什么证据、还剩什么；没有核实到则明确写本次未找到，不编造发展链。

大纲条目应写出上述问题的实际答案和阶段性结论，不得用“比较 A/B”“考察效率”“核对局限”等工作指令代替调研结果。
开头先说明任务、使用目标和不解决的具体后果，再引出技术困难；不能用“必须”“重要”或抽象判断代替动机。
例子、方法和结果围绕总问题推进。先安排观点之间的依赖，再选择支持观点的论文；同一判断下比较相关设计，不按论文逐个另起话题。首次出现术语时，先说明它处理什么、做什么，再给名称。
并列分支须有共同目标和比较依据；分支结束要回到总问题，不硬造因果或发展顺序。新对象仅用于说明已有解释的适用边界时简短处理；无助于结论的旁支删去，不能靠过渡词或重复“仍有问题”连接独立段落。
论文用于支撑解释，不能按年份逐篇串讲。并行路线分别展开；只有明确依据才能写为继承、针对性改进或取代关系。
按主张选择引用：单篇结果只能支撑该案例；概括共同困难或比较路线时，须有相应范围的互补证据。不规定每段引用数量，也不把单篇局限写成领域共识。
比较须保留任务、数据和运行条件的差异；区分原文结果、本次分析和未来设想。找不到证据不等于该方向不存在。

## 6. 写入 TeX 与 temp

按第2节已确认的目录，将第5节形成的实质大纲写入项目实际使用的 TeX 主稿和目标章节，保留问题、段落判断及其联系，不扩写成正文。依据项目入口或编译配置定位主稿，只更新本轮约定的语言；已有正文保留，仅更新原大纲或追加待审大纲，不另建 `outline.md`。为大纲节点保留或设置稳定标签，沿用已有 `SYNC-ID`。

在当前稿件目录新建或复用 `temp/<chapter-id>/`，按 [章节参考文献格式](references/chapter-records.md) 保存同一组记录的两种表示：

- `references.md`：简短调研结论；逐篇书目信息、准入依据、摘要概述，以及研究问题、动机、方法、局限性、贡献五项分析和对应证据位置；再列本章用途、大纲映射及未解决问题。参考过但未选用、待核验和排除记录按实际阅读保留，不补造五项内容。
- `references.json`：同一组文献的五项分析、证据条目、本章用途、大纲及论据映射、筛选依据、检索记录和检查结果，供 `write-review` 与后续 `cite` 复用。五项存入既有 `problem_analysis`，具体支持内容存入 `evidence`，不另建一套文献库。

两种表示中的文献、证据与大纲 ID 对应一致；缺项原因、阅读范围与核验状态同步保留。复用原库 ID，库外论文使用章节临时 ID；不自动修改共享 BibTeX、正式文献库或清理 `temp`，也不为单次交付另建大套生成与验证脚本。

要求双语时保持两语的大纲结构、论点、证据边界及对应标签一致。内容稳定后按项目配置编译本轮修改的语言并查看目标页，修复本轮引入的错误或阅读问题；无需为独立预览反复改分页或导出截图。

仅在对话中测试时，展示实质大纲、逐篇五项记录及必要的证据与缺口，不写文件、不编译；文件、格式和编译检查记为不适用。

## 7. 检查、补救与交付

对照实际大纲和文献包检查，先看内容与论据，再看写入结果；不能用计划写全、引用数量或脚本通过代替内容判断。

| 检查什么 | 不通过时怎么办 |
| --- | --- |
| 范围与目录符合第1、2节已确认的决定，与相邻章节分工清楚 | 回到相应步骤补足缺失信息；只有范围或目录确需变更时重新确认，不重复询问已有决定。 |
| 拟采用文献相关且达标；逐篇五项可辨认，原文位置、版本、阅读范围和缺项原因如实，关键设计未被遗漏 | 按第3、4节补核筛选依据或定向补读，纠正、补齐相应记录；未取得的内容保留缺口，不能以摘要或模型经验补全。 |
| 只读实际大纲，能复述整节问题、各段推进及最终结论，满足第5节的解释要求；没有技术介绍流水账或缺失前提 | 回到第5节重组、合并或删除旁支，补清有依据的机制与句段关系；缺事实转第4节。真正并列的内容说明共同目标，不强造递进，也不只添连接词。 |
| 综合判断与证据范围相称，条件差异和反例未被抹去；声称的因果、局限及后续改进关系有依据 | 定向核对相关原文，收窄或修正概括；发展关系无法证实时改作并行比较或明确未找到回应，不能用年份推导继承与改进。 |
| 两种文献包内容及大纲映射一致，ID 可定位、JSON 可解析；适用时双语一致，TeX 编译后目标内容完整可读 | 按第6节修正不一致的记录、映射或输出；修复本轮引入的编译与阅读问题。不适用的输出检查注明原因，不列为失败。 |

修改后只复查受影响的记录、段落及相关结论。围绕明确缺口尝试可行的补读或新来源；无新的有效路径时停止重复检索，保留可成立的部分，说明缺口、影响与下一步，不通过删除已确认的研究问题规避失败。

完成状态区分材料边界与执行缺失：已核查的范围内未找到某项陈述或后续回应，若已如实记录且不损害核心判断，不自动判为未完成；核心判断仍缺依据、所需原文未取得或适用的必需检查未完成，则标为 `needs_work`。只有其余适用检查通过且剩余缺项均属已说明的材料边界时，才记为 `complete`。这表示本轮调研交付完成，不代表用户已认可；不得把工具不可用或检查未执行记为通过，也不自行放宽选材条件。

交付大纲和文献包链接，或用户要求的对话结果，简述内容与证据、适用的双语和技术检查、剩余问题及整体状态。后续写作使用的主张若发生变化，仍须复核相应证据。
