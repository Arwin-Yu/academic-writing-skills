# 正文执行检查

目的：防止“读过技能”和“写了自评”冒充实际改写。每次使用 rewrite 都读取本页。

先只读正文与必要上下文，按[rewrite第二步](../SKILL.md)的六项找出理解断点。每项用正文回答具体问题，不只填写“通过”。授权范围内另有机制时，检查一个未被用户点名的机制；清楚且准确的文字保留。补充事实必须有已有材料支持，否则按任务授权返回paperwrite或列出缺口。

复述既要覆盖主要机制，也要覆盖所改段落与相邻段落的联系。术语定义和步骤齐全，仍需检查读者能否理解必要性及作用；句子变短，仍需检查角色、参数传递和前后因果是否完整。前文已说明的前提标明位置，不重复解释；不适用项说明原因，不扩展任务。
复述时须说清每句实际增加的机制、证据或局限；仅能复述为“作者报告／讨论了这一主题”的句子应重写或删除，不把必要的证据归属一并删去。

文件任务在本轮工作目录保存初稿、最终稿及 `review.json`，字段如下：

- `draft_file`、`final_file`：相对本记录目录的路径。
- `final_sha256`：最终稿 SHA-256；正文有变动就重新核查并更新。
- `repairs`：每项含 `before`（初稿原句）、`gap`（缺失前提）、`after`（改稿原句）；流程或跨段修复可引用整段，不能只截取连接词。
- `reader_traces`：覆盖六项适用内容、主要机制和段落联系；每项含 `question`、`answer`（仅凭正文的具体复述）、`evidence`（最终稿原句列表）。参数检查复述形式、来源和用途；流程检查复述各角色及数据传递；跨段检查引用相邻段落的相关片段，解释承接的具体问题。只重复模块名或依赖未写出的前提，不能通过。
- `content_judgment`：原意与结论强度、跨节重复、总结依据及六项不适用理由的具体检查结果。
- `unresolved`：剩余问题列表；非空时不能标记内容完成。
- `reviewer`：如实注明同一助手复核或实际独立审阅。

用本技能目录下 `scripts/check_review.py` 的实际路径运行检查，并传入本轮 `review.json` 的路径。它只验证引用片段、最终版本和记录完整性，不验证六项语义覆盖。按最终正文复读后才能判断内容完成；发现断点就继续改写，缺少证据则记录在`unresolved`。对话测试直接展示必要修改，不强制生成文件。

## 典型断点

- “所用面部模型和跟踪器仍未完全分离身份与表情，作者报告了由此带来的限制。”前半已说明局限，后半仅转述文献行为；删去后半并保留引用即可。若局限尚未说明，应据已有证据写出具体问题及后果。
- “优化特征和颜色解码器。”缺少：特征不是颜色，渲染器经解码才得到颜色，所以绘画目标需要反求内部数值；修改共享解码器也可能改变别处。
- “颜色图可以直接编辑，但烘焙会损坏几何。”缺少：烘焙还生成尺寸、旋转等几何属性图；重表示这些量也会改变细小结构。
- “纹理对应保持不变。”缺少：贴画写入颜色图后，同一皮肤部位运动时仍读取图中原来的位置，所以贴画随皮肤移动。
- “从视频取得表情，输入头像。”缺少：传递的是什么控制量、由哪个模型估计、头像怎样使用；新名称和向量维数不能代替这些关系。
- “持续驱动还需减少计算。”缺少：前述方法反复执行什么、为何影响跟随速度、后续方法省去了哪一步。不能只加过渡词。

例子用于辨认缺失关系，不能据此给其他方法添加未经证实的机制。执行记录不能保证今后绝无错误，也不能替代作者认可。
