# 文献库与引用计划

本文件用于 `write-paper` 的建库、证据复用与引用检查。文献库是整篇论文的共同基础，续写单章时复用已有成果，不重新检索40篇。创建或修改技能、讨论模板时不启动文献调研。

## 1. 确定范围并形成入选库

先明确主题、目标任务、拟解决问题、关键词和检索范围；已有确认不重复询问，缺少关键信息时先补足。复用项目已有文献库与原文缓存，已有库内论文也须执行以下准入要求。

`write-paper` 统一继承 `deepresearch` 的文献筛选门槛。每篇论文须与本研究相关，并且**至少满足以下一项**才能入选；这些要求在本包独立执行时同样适用。

| 准入条件（三项满足任一项） | 核验要求 |
| --- | --- |
| 发表于 CVPR、ICCV、ECCV、AAAI、ICLR、NeurIPS、ACL、EMNLP 正式主会 | 查官方主会论文记录；Workshop 和 Findings 不按此项通过，仍可检查另两项。 |
| 所在期刊最新 JCR 年度 JIF **大于10** | 以检索时最新发布年度为准，查 Clarivate JCR 或明确标注该年度的期刊官网。 |
| 单篇论文引用次数 **大于5000** | 优先 Google Scholar，不可用时用 Semantic Scholar 或 OpenAlex，记录来源和日期。 |

JIF恰为10或引用恰为5000均不通过对应条件；不能用CiteScore替代JIF、用作者总引用代替单篇引用或相加数据库计数。最新年度JIF未取得时该项待核验，不用旧值通过。已核实一项通过即可，不必查完三项；无通过项且仍有条件未知时标为待核验，三项均不满足则排除。预印本核对已录用版本或按另两项判断，不凭预印本身份通过主会条件。

逐篇保存筛选决定、通过条件、官方记录或指标来源及核验日期；待核验候选不计入40篇，不能为凑数放宽门槛。达标还须通过相关性和拟用主张的原文核验。

deepresearch可用时复用其检索与阅读流程；不可用时按本文件执行。从Google Scholar检索关键词、英文同义词、任务与机制，追踪代表论文的参考文献及后续引用，同时查看近期进展。入口不可用时改用Semantic Scholar或OpenAlex，结合DBLP、官方论文集和作者原文。记录查询、日期、实际查看范围及缺口，无新路径时停止重复尝试。

正文起草前，入选库须有不少于40篇去重且符合上述门槛、完成必要阅读的独立文献，覆盖背景、代表方案、最接近工作、技术基础及近期进展。预印本与对应发表版合并计数，期刊扩展版核对是否属于同一工作；跨章复用不重复计数，未选用及排除记录不计入入选库。

## 2. 逐篇理解并记录依据

每篇入选文献分别记录五项，不能用整段摘要或“本章用途”代替：

| 记录项 | 内容与主要阅读位置 |
| --- | --- |
| 研究问题 | 具体任务、困难与问题条件；优先摘要，不足时补引言。 |
| 动机 | 现有不足、解决理由及后果；优先摘要，不足时补引言，与研究问题分开。 |
| 方法 | 核心思路、关键操作及作用依据；以方法、图式和公式为主，讨论与结论补充。 |
| 局限性 | 假设、条件、失败与剩余问题；查方法、讨论和结论，实际失败或性能边界核对实验。 |
| 贡献 | 作者声称的新方法、理论、数据或发现；优先引言末，效果核对实验，理论结论核对推导。 |

保留作者、题名、版本、链接、筛选依据及实际阅读范围。每项概述关联证据ID；证据含具体陈述、原文简短转述、章节/页码/图表公式位置、条件和核验状态。贡献声明不是效果验证，作者报告、实验观察与本文解释分清；`verified` 仅表示原文支持对应陈述，不表示独立复现。

“未取得所需章节”与“在已读范围内未找到陈述”分开，未知内容留缺。若缺口影响拟采用主张，定向补读或收窄主张；不把未报告写成不能实现，不以局部阅读冒称全文核验。

## 3. 按大章节预分配正文引用

每篇入选文献在写作前至少分配一个大章节，如Introduction、Related Work、Method、Results、Discussion或Conclusion，同篇可分配多章。预分配记录章节、用途与依据；具体放在哪个段落或句子，由实际写作时的论点决定。

| 内容 | 要求 |
| --- | --- |
| 文献ID、引用键 | 对应唯一文献及实际使用版本，复用已有标识。 |
| 计划章节 | 指定一个或多个大章节，使用稿件实际章节名。 |
| 本章用途 | 概述用于背景、方法溯源、比较、支持、反驳或限定什么认识。 |
| 原文依据 | 关联证据ID、原文位置及适用条件，不能只有论文标题。 |
| 实际引用与状态 | 按章节记录已分配、已引用或待修复，核查实际引文是否支持相邻主张。 |

以references.md展示逐篇记录和章节分配表，references.json保存同一组信息。沿用problem_analysis、evidence、chapter_use与outline.argument等已有字段，把计划附在章节记录中，不改造整套库或重复存储论文。引用跨章迁移、用途或证据变化时更新计划。

## 4. 按章节取用

Introduction重点用文献建立问题价值、已有进展及研究缺口；Related Work综合共同问题、技术基础与最接近工作的差异。Method核对借鉴方法和设计前提，Results核对数据集、指标、基线和实验协议来源，Discussion联系已有发现与边界。Conclusion只收束已论证认识，不为分配文献增加新主张。各章不设平均配额。

写作时从本章分配的文献中按当前论点选取依据，引用紧邻真正支持的陈述，不把来源整理成逐篇技术流水账。本文方法和实验结论须有自己的材料，不能用文献结果代替。新增引用先核验、入库和分配；跨章调整、引用用途或证据变化时更新章节计划。

## 5. 区分章节检查与全篇检查

单段任务检查本段实际引用与主张是否匹配，并记录本章已引、待引文献；无需在一个段落中用完该章全部文献。整章完成时核查本章预分配文献是否实际引用或已合理改配。其他章节仍待写不阻碍当前章节完成，也不能据此宣称整篇完成。

最终整篇须满足：入选库不少于40篇；每篇至少一个预分配大章节，并在正文实际引用至少一次；未分配与未引用的入选文献均为零。只列入参考文献表、通过 `nocite` 加入或仅标记“已引用”不算落实，须对照实际正文及支持关系。

漏引就补足有依据的论述或调整位置；证据不支持时修正主张、改配适当位置或替换文献，替换后仍满足数量和引用要求，不能无关挂引。数量不足、核心证据缺失或引用仍未落实时保留已完成部分，列明缺口与影响，不能标记整篇完成。
