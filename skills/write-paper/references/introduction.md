# Introduction：根据研究问题组织论证

引言让读者理解研究背景、问题、已有认识、本文回应及贡献。以下是可调整的段落职责，不预设主题、研究类型、具体方法、问题数量或贡献类别。根据论文材料、作者要求及投稿规范合并、拆分或调整，不为填满结构创造内容。

## 1. 确定本篇文章的组织方式

先明确研究对象、主要问题、已有认识、本文增加的认识，以及支撑它的材料或论证。理论、实证、观察、系统和数据资源等研究可采用不同展开顺序，不强制走同一条技术或实验流程。

有作者认可版本时，只提炼适用于当前任务的组织和表达特点：段落职责、推理展开程度、句间承接、术语解释及证据呈现。同一论文重写时保留支持论点的必要内容；用于不同论文时不移植原文的主题、例子、概念、步骤、结果和贡献类别。没有参照时，采用具体、连贯、便于目标读者理解的说明方式，不默认调用上一次项目的范文。

| 常见职责 | 读者需要理解的内容 |
| --- | --- |
| **I1. 背景、重要性与现状** | 研究什么 → 为什么值得研究 → 与本文主题相关的已有认识或做法是什么 → 自然引出进一步考察的方向。给出足够背景后再收窄，不在开头堆入尚无上下文的具体问题。若研究对象是某种工具、机制或方法，说明它怎样起作用，使读者理解它为何可能回答该问题，不只给出名称。 |
| **I2. 问题与不足** | 承接已有认识或做法 → 说明尚不能回答或保证什么 → 解释原因及后果 → 明确本文关注的问题。指出不能保证某个性质时，宜给一个具体场景，说明该性质不满足时会怎样出错，并附引用或标 `[?]`。概念区分只在有助于辨清问题时引入，不固定概念数量。 |
| **I3. 相关进展与本文思路** | 围绕问题组织已有回答 → 说明它们共同建立了什么、留下什么 → 交代本文思路的依据及适用理由 → 明确如何推进认识。必要时与I2合并或交叉组织，不逐篇罗列文献。 |
| **I4. 本文研究如何回应问题** | 介绍关键研究对象、依据、方法或论证 → 解释理解研究所必需的操作或推理 → 说明它如何回应前述问题。顺序服从研究实际和读者理解，不强制先收集数据、再提出方法。 |
| **I5. 主要发现与贡献** | 说明本文得到什么 → 用必要证据交代其意义 → 识别新增的认识或研究产出及其范围。是否使用贡献列表、列多少项及怎样分类，取决于真实贡献和写作要求。 |

## 2. 补足推理，解释研究怎样起作用

关键判断要有必要前提。若指出现有做法不能保证某个性质，应说明它实际解决或约束什么、为什么仍不足以保证该性质，而不只宣布存在缺口。若区分多个概念，应解释区别为何影响当前问题，不以概念命名代替论证。后文的方法、评估或讨论依赖该区分组织时，在首次引入处给出简短名称和可检验的定义，此后统一使用；没有后续用途的区分不必命名。

方法或研究思路应展开到读者能够理解其作用的程度。依据实际研究说明材料或对象是什么，做了什么处理、比较或推理，得到什么，以及这些步骤怎样帮助回答问题。必要的条件、对象层次和中间关系不能压成一个模块名或抽象改进声明；无关实现细节也不必全部介绍。

研究依赖特定观察或材料时，交代它与设计或论证的关系。理论研究可从问题、条件和关键推理展开；其他研究按自身的证据与方法组织。不把某种研究的常用流程写成所有文章的先后顺序。

## 3. 用证据说明发现和贡献

先明确发现及其依据，再决定哪些细节有助于理解和判断。有比较时说明比较对象、条件和含义；没有对照实验的研究不创造基线。数学结论、定性观察、资源能力或其他产出，采用与其相符的支撑方式，不一律改写成性能提升。

数字、术语、图表结果和研究配置按论证需要选择，不把全部结果压缩进引言，也不规定只能保留某个数量的数字。引言中的发现以结论及其关键依据为主；数据划分、样本量、重复次数、统计区间等设置留给对应章节，除非不交代就无法理解结论的含义或范围。必要的不确定性、相反证据和适用条件应保留。已经准确限定的主张无需反复否定未提出的更强命题；限定也不能被省略到改变结论。

贡献以实际新增的认识或产出组织，避免重复研究动作、输入材料或模块清单。有两项以上性质不同的贡献且投稿要求未禁止时，默认使用贡献列表，以简短加粗标题加完整句说明做了什么、建立了什么或为何有价值；只有一项核心贡献时用正文陈述即可。不预设数据、模型、评估等固定类别，也不拆分同一贡献凑数。每条写出前文结果未说明的认识或产出，不复述上一段的结论。条目形式服从作者和投稿要求。

## 4. 文风与引证

- 使用具体对象和动作表达关键关系。首次出现的术语补足目标读者理解所需的含义，不用另一个抽象术语替代解释。
- 后句承接前句已经建立的信息，再推进一步。用因果、条件、比较或转折连接真实关系，不靠连接词跳过前提。
- 嵌套关系过多时拆句；缩短时先删旁支和重复，不删支撑判断的关键解释。句长与语气根据读者、语言和体裁调整。
- 文献围绕同一问题及已有回答的关系组织。保留使推理成立的机制和差异，不把逐篇阅读记录搬进正文；跨任务借鉴须解释适用条件。
- 每处引用支持相邻主张，按 `write-paper` 第3节先写论证、再逐处配引、最后扫描最接近工作与反例。候选预分配不构成引用配额，未采用不欠引。查过文献库仍缺直接来源时保留 `[?]` 并注明所需依据，不能用占位使未经核实的事实成为定论。

## 5. 检查成稿与规则的通用性

先只读正文，检查读者能否连续理解：研究对象和价值、已有认识、问题及其原因、本文怎样回应、结论与贡献。分别检查段落职责、句间推理、解释深度和引用准确性；结构齐全或格式检查通过不能代替内容检查。

有作者参照时，比较新稿是否采用了相应的解释方式和信息取舍，不追求字面复现。记录实际不匹配句、原因及修复；需要验证技能效果时，另存生成稿、比较记录和修订版本，说明实际测试范围，不把单篇成功称为普遍验证。

更新规则时，将写作原则与校准案例分开。案例的题材、专名、数据、方法、指标、概念数量和贡献分类留在本次工作记录，不作为技能默认要求。可用不同主题和研究类型检查适用性：规则应能据材料改变组织方式，而不是要求新研究补齐原案例的内容。

测试和示例不得修改用户明确要求保留的正文。用户只要对话稿或禁止改原稿时，另存测试输出，不编译原工程。
