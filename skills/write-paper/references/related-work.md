# Related Work：从本文问题倒推组织

相关工作向读者说明：要回答本文的研究问题，已有研究已经提供了什么、还缺什么，以及这些缺口怎样引出本文的做法。它不是按文献类型整理的综述。

## 1. 从前文问题倒推子章节

先从Introduction（或已有的问题陈述）提取：本文的研究问题、提出的空白、命名并定义的关键概念，以及本文主张的贡献。再问：这个问题要成立并得到回答，依赖哪几个前提或子问题？例如“已有做法能否保证某性质”“所借用的信息来源或技术是否已被用于类似目的、效果如何”“所需的评价方式是否已有依据”。每个子问题对应它所属的研究领域或方向，按领域设子章节；领域决定在哪里找文献，子问题决定这一节怎样组织和比较这些文献。

- 子章节**不超过四节**。子问题多于四个时合并相近者，或把次要内容并入相关小节；内容少时可不分小节。
- 子章节标题使用该研究领域或方向的常规名称，便于读者定位，例如“某任务中的某技术”“某类数据用于某目的”“某性质的评估”；不把论点、结论或研究问题写成标题。
- 每节首句说明本节在该领域中考察什么、与本文哪个问题有关，后文围绕这个子问题组织；不能因标题是领域名就退回到逐篇综述该领域。
- 比较维度优先使用前文已命名的概念和问题，不以单篇文献自带的特点（如各自的技术名称或设计口号）作为比较轴。

## 2. 每段的推进方式

每段围绕一个判断推进，常见顺序为：

**综合认识 → 证据 → 缺口 → 与本文的关系**

1. 先陈述这组文献共同说明了什么，用前文的概念表述。
2. 用各篇的具体证据支撑、限定或反驳该判断；只介绍比较所需的机制和条件，其余细节删去。多篇文献之间交代共同问题及各自回答的关系，而不是依次介绍。
3. 说明已有工作还未回答什么，以及原因（对象不同、条件不同、未检验某性质等）。
4. 说明该缺口与本文研究问题的关系，以及本文怎样回应。只写与研究问题有关的差异，不写实现层面的区别；方法设计的具体理由留给Method，此处只交代文献怎样支撑这一选择。

以下写法可在小节内部按需使用，不再作为固定的分节方式：

| 写法 | 适用情形 |
| --- | --- |
| 同一问题下的已有方案 | 比较各方案对前文问题解决到哪一步、在什么条件下、代价如何。 |
| 相关技术基础 | 说明本文借用的思想原本解决什么、在什么条件下有效，本文任务的差异及继承或调整之处。 |
| 与最接近工作的关系 | 说明为何是最接近对象、共享什么、本文改变了哪个设计/假设/对象，以及哪些差异需要验证。 |

## 3. 引用与检查

按问题和论证关系组织引用，避免逐篇介绍技术。重复引用同一文献时，应承担不同且必要的论证作用。不能因单篇局限概括整个领域，不将年份先后写成继承或针对性改进。

完成后检查：
- **一句话检验：** 每个子章节能否概括为“已有工作说明了X，但尚未回答Y；本文的问题需要Y”。不能概括则重组。
- **前文衔接：** 每个子章节能否对应到前文的某个具体问题、空白或概念；前文已命名的概念是否被沿用。
- **标题检验：** 子章节标题是否为读者熟悉的领域或方向名称，而不是论点句或问句。
- **删句检验：** 删去某篇文献的句子后段落判断是否仍成立而不受影响；若是，该句只是罗列，改写为论证的一步或删去。
